# 生产设计输入：研发环境与技术边界包

DSH 在 POC 用户确认后汇总，交 Grok 及其参与设计的内部 agent 共用。记录实际核查时间；环境变化时更新相关项，不机械重扫。仅包含与本项目研发和交付相关的信息，不收集或传递密钥、令牌和无关个人数据。

```text
项目／边界包版本／核查时间：
用户目标与锁定要求：权威需求位置、明确排除项
POC：版本、产物绝对路径、体验方式
用户确认：原话、时间、确认的效果与范围
POC尚未证明：规模、长时运行、完整流程、主观质量等具体限制

软件与运行时：工具名称、版本、可执行路径、系统、相关硬件/资源限制
模型／API／插件：实际暴露能力、输入输出限制、已验证参数、账户可用性
依赖与权限：已有依赖、网络可用性、允许读写目录、实际审批边界
资产与格式：已有素材、字体、授权、工程格式、最终输出规格
预算与时限：用户授权额度、核查时余额、单次成本估算、停止条件

已验证链路：输入→工具/模型→输出、证据路径、验证时间、适用范围
已失败链路：现象、尝试与结果、根因是否确认、当前替代方法
新增能力：调研来源、安装/配置状态、实际验证结果与回退路径
能力分类：已端到端验证／已具备但未验证／需新增验证／明确不可用
POC资产复用：可直接复用、临时实现需重构、生产仍需补齐的内容

设计边界：本轮可承诺项、待验证扩展、不可承诺项
待验证扩展：业务价值、最小实验、时间/费用、所需授权、失败回退
交接：DSH负责派单、Grok负责设计和质检、Codex负责实现；现有在途任务
```

POC 成功证明的只是该体验路径与确认范围；不自动证明全部生产规模或质量达标。Grok 对重要能力引用本包证据，不能把“可能支持”写成生产承诺。DSH 发现方案越界时，返回具体不符项或安排针对性验证，避免边开发边反复改整套方案。
